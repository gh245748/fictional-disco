# Meşk v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Meşk v1, a Turkish-language Flutter app for iPhone and Android that turns practice hours into skill levels (1–99, then hidden tiers), with linked-skill bonus XP, an Obsidian-like skill graph, character stats, a customizable pomodoro, habits and goals, all stored on-device with JSON backup.

**Architecture:** A pure-Dart `lib/domain/` layer holds every rule (curve, titles, XP/bonus, stats, habits, goals, timer state machine, achievements, graph layout) and is unit-tested first. `lib/data/` persists domain models in sembast and runs every XP-changing mutation through one `LogPipeline` that writes bonus awards, level/tier events, goal completions and achievements and returns celebrations. `lib/features/` holds Riverpod-driven screens built on `lib/ui/` theme tokens taken from the approved "Klasik" mockup.

**Tech Stack:** Flutter 3.50.1 (Dart 3.14.0), flutter_riverpod 3.5, go_router 18.1, sembast 3.10, flutter_local_notifications 23.0 + timezone + flutter_timezone, intl (tr), share_plus, file_picker, path_provider, uuid; GitHub Actions for Android APK and iOS TestFlight.

**Spec:** `docs/superpowers/specs/2026-11-21-mesk-design.md` (section numbers below, e.g. §5.7, refer to it). Visual reference: https://claude.ai/artifact/G7E44RvtCjL1WEyb4Uf5iv, page "Yazı tipleri", artboard "1 · Klasik".

## Global Constraints

- Flutter **3.50.1** stable, Dart 3.14.0; installed at `$HOME/sdk/flutter` (`export PATH="$HOME/sdk/flutter/bin:$PATH"` in every shell). Dart package name `mesk`.
- Platforms: iOS ≥ **15.0**, Android minSdk **26**; portrait only. Bundle/application id **`com.mesk.app`**, display name **Meşk**.
- Turkish UI only, locale `tr_TR`: decimal comma, percent as `%27`, thousands separator `.`, week starts Monday. Uppercase labels must use `trUpper` (never `String.toUpperCase`), name sorting must use `trCompare`.
- Fonts bundled from `assets/fonts/` (OFL): Cormorant Garamond 500, 600, 500-italic; Manrope 400, 500, 600, 700. No runtime font downloads, no network calls, no analytics.
- Colors, type scale, radii and motion exactly as §5.13 (tokens in Task 14).
- Touch targets ≥ 44 logical px; text contrast ≥ 4.5:1; text scale clamped to 1.3.
- All durations are integer **seconds**; all instants are stored as UTC plus the device's UTC offset in minutes at that instant.
- Levels come from XP (real + bonus); goals use real time only (prior experience included); habits, daily totals and pace exclude prior experience (§5.1, §5.2).
- Nothing decays over time. Numbers go down only when the user edits/deletes data.
- **Storage deviation from §6.1:** use **sembast 3.10** (pure Dart) instead of drift/SQLite. drift 2.35 needs `package:sqlite3` 3.x, whose build hook downloads native SQLite from GitHub releases at build time, which this container cannot reach. sembast keeps §5.14's requirements: local, versioned schema, migrations in code, JSON backup.
- **Visual verification deviation from §6.3:** screenshots come from golden tests (PNG files rendered by `flutter test` with the real fonts), not a web build. This avoids web database plumbing and gives the same result.
- Dependencies: only those added in Task 1 (plus `flutter_launcher_icons` in Task 26). Anything else needs a one-line justification in the commit message.
- Every commit message ends with these two trailer lines:

## Review Focus

1. **Turkish letters:** labels and sorting with i/İ, ı/I, ç, ğ, ö, ş, ü. `trUpper('cumartesi')` must give `CUMARTESİ`, and "Çizim" must sort after "Cesaret", not after "Zihin". Tested in Task 3 and used in Task 16.
2. **Clock and day boundaries:**
   - The device clock jumps backwards during a running timer.
   - The user travels between time zones.
   - An entry falls near `dayStartHour`.
   Expected: no negative durations, and an entry stays on the day it was recorded. Tested in Tasks 3, 6 and 8.
3. **Cascading edits and deletes:** deleting a linked skill that has habits and a goal, editing an entry's duration, and level drops after deletion. Expected: no orphan records or crashes, bonus rescaled or removed, level achievements re-locked. Tested in Task 12.
4. **Bad backup files:** malformed JSON, another app's JSON, or a newer backup version must be rejected with a Turkish message, leaving the data untouched. Tested in Task 13.
5. **Missing notification permission:** if notifications are denied or exact alarms are unavailable, onboarding, the timer and habit reminders must keep working without crashing. Tested in Tasks 15, 18 and 19.

- [ ] **Step 4: Implement the curve**

`thresholdSeconds(L) = (3600 * 1000 * (0.02*x + 0.98*pow(x, 2.5))).round()`, where `x = (L-1)/98`. - [ ] **Step 3: Implement**

- [ ] **Step 3: Implement `LogPipeline`**

Each mutating call runs in one `database.transaction`:
1. Load the full dataset (it is small).
2. Compute XP before the mutation.
3. Apply the mutation:
   - `saveEntry`: write the entry plus its `awardsForEntry` using the current links and `settings.bonusRateBp`.
   - `updateEntry`: replace the entry and `rescaleAwards`.
   - `deleteEntry`: remove the entry and its awards.
4. Compute XP after and run `diffLevels`. Upsert `LevelReached` for each level in `(from, to]`, plus level 1 on the first tracked entry. Delete rows above the new level, and do the same for `TierReached`.
5. Complete active goals that reached their target.
6. Unlock any new `metAchievementKeys`.
7. Return the celebrations in this order: level and tier cards, goal cards, achievement cards.

`recomputeAll` does steps 4–6 for all skills without returning celebrations and without re-dating existing rows.
